Open design questions

Decisions this review should settle — please cite questions by number. 1–7 stand from round one; 8 and 9 are new. The readers now run on real data, so argue with the behaviour, not just the pictures.

  1. Per-book mode defaults

    Which books open in Study, Facsimile, or Explore? The obvious cases are easy — E17’s dictionary entries want Study, the Cushing manuscript wants Explore — but should the default table be editorial (curated per book) or heuristic (derived from format and tier)? And may a user’s override outlive the session?

    Seereader-codexreader-explore

  2. Sidebar: tabs or stacked

    Contents, On this page, Article, Appearance — four tabs hide three panels at any moment, yet Contents and On this page are often wanted together. A single stacked scroll with collapsible sections keeps both visible but gets long on dense pages. The codex mockup ships tabs; is that right?

    Seereader-codex

  3. Shape of the entity relevance metric

    “On this page” ranks entity mentions by a new per-page relevance attribute. What feeds it — mention count on the page, proximity to a rubric, entity tier, cross-corpus degree? Should it be computed at build time and pinned with the corpus hashes, and can a curator override the ranking for a page?

    Seereader-codex

  4. Paged vs continuous for codices

    Is a codex’s default OpenSeadragon profile paged openings or a continuous vertical strip? Continuous suits long reading and matches the streaming model; paged respects the object and its openings. Per-book choice, per-user preference, or per-mode (Facsimile paged, Study continuous)?

    Seereader-codex

  5. Embed API surface

    Are excerpt, card, and explore the whole surface (plus a chrome-less full variant, not demoed), or do embeds also need scheme/mode parameters, entity hover, and a postMessage channel so a parent article can drive the excerpt (scroll to a passage, light an entity)? Every addition is API we must keep stable.

    Seereader-explore

  6. How far basic mode strips

    Basic mode hides layer checkboxes, confidence, and engine chrome. Should it also suppress region outlines and entity underlines, leaving plain text and image? Diplomatic exactness argues that visible uncertainty must survive even in basic mode — where exactly is the line?

    Seereader-codex

  7. Compare-view scope

    The Dioscorides hub compares two copies of one edition (E46 vs E47) page by page. Does the same view stretch to cross-version alignment — EB01’s hieratic against EB02’s German — or is that a different tool? And does compare live on the work hub, inside the reader, or both?

    Seework-dioscoridesoverview-landmark

  8. Which art direction — A, B, or C?

    The directions page draws three complete visual temperaments over the same corpus material. Which becomes the product? May elements cross-pollinate — one direction’s facsimile chrome with another’s reading typography — or does mixing dilute the voice? Because every mockup already runs on tokens, the winner lands as a palette and type ramp, not a rebuild.

    Seedirections

  9. Module API: are the seams right?

    The readers now compose seven small modules behind a documented contract — bus event vocabulary, the store’s layer priority, viewer profiles, the linker’s highlight weights, chrome’s ownership of appearance. Before implementation hardens: is anything in the wrong module, did any page have to hack around a seam, and are these the event names we want to be stable?

    Seelib/API.mdcomponents
